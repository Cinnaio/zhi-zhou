# 历史阅读数据检查与恢复（2026-10-10）

## 用户入口

登录后打开「个人中心 → 阅读数据」。页面显示当前账号，并提供两项操作：

- 检查历史数据：只读预览失效或章节错配的书签、旧作品名/章节名/排序以及异常阅读进度。逐项说明删除、更新或清除，再通过确认弹窗修复。更新有效书签时保留备注与原更新时间；异常进度百分比归一化，无效章节进度写入时间递增的清除标记。每批最多 100 项，可继续检查。
- 恢复旧浏览器数据：只有用户点击预览时才提交旧数据；先列出添加与跳过项，再勾选归属确认并通过带有目标账号的弹窗恢复。已存在的云端书签、书架、阅读进度及进度清除标记不会覆盖。恢复后保留原始浏览器键。

当前阶段提供每个账号的自助操作。检查与恢复遵循服务端实际内容权限及当前阅读模式；不返回受限作品的名称或错配章节的名称。普通书签、最近阅读、书架与单书进度接口同步过滤失效和章节错配的历史关联，书签展示当前作品与章节名称。

旧版公共键 `novel_bookmarks`、`novel_reading_history`、`novel_bookshelf` 没有账号归属，只显式恢复这些键，不迁入游客缓存、pending 缓存或其他账号的缓存。忽略客户端缓存的书名、章节名及书签 ID，由服务端确认作品/章节关系并生成记录 ID。每类最多 500 条；格式错误或超限类别给出提示并保留原始内容。合法类别仍可恢复。恢复预览使用批量查询，避免每条记录分别访问数据库。

## 确认、事务与回执

迁移 `050_reading_data_operations.sql` 新增账号所属回执表，随 API 正常启动自动执行。回执包含操作标识、类型、数量、时间及请求摘要，不存储书签备注、作品名称或旧浏览器原始内容；页面显示最近十次。

预览摘要绑定账号、实际阅读权限、十分钟有效期及数据库快照/恢复计划。确认时使用 repeatable-read 事务重新生成计划并验证摘要；数据变化、权限变化或过期返回 409，要求重新预览。操作标识在账号内唯一，相同请求重试返回原回执，其他请求复用该标识被拒绝。

修复更新附带原行快照匹配，整批业务变更与回执在同一事务提交。另一设备在应用过程中修改目标记录，或回执写入失败，整批回滚；保留另一设备已提交的修改。恢复只插入缺少的记录，并使用冲突保护。原有进度清除标记阻止旧数据复活。

前端在预览、确认及请求结束时验证会话、账号缓存范围与组件生命周期。切换账号或阅读模式会重建面板，旧异步结果不能写入当前界面或清除其他账号缓存。确认期间浏览器旧键变化也要求重新预览。只有实际修复的进度缓存会被失效处理。

## 验证方式

API 测试覆盖认证、确认账号、只读预览、内容权限、过期/变更拒绝、修复、恢复不覆盖、回执重试、事务回滚及 500 条边界。组件测试覆盖归属勾选、确认取消、旧键变化、账号切换、失败保留和缓存隔离。

`npm run test:backup-integration` 额外创建 `backup_integration_reading_data` 临时库，以两个真实 PostgreSQL 连接验证修复途中并发冲突回滚、并发恢复去重和响应丢失后重试。脚本仍要求全部执行、零跳过，结束后清理临时 PostgreSQL/SFTP；独立 `Backup recovery` 工作流执行同一脚本。已有旧版本备份恢复测试也覆盖新增迁移。

前端浏览器验证使用构建后的 Vite preview 与虚构 API 夹具，不接触部署数据：

```bash
# 终端一
npm run build --workspace=@zhi-zhou/web
npm run preview --workspace=@zhi-zhou/web -- --host 127.0.0.1 --port 5189
# 终端二
node scripts/check-reading-data.mjs
```

验证 1440、390、360 像素和明暗主题下的预览、确认/取消、原始数据保留、修复、账号切换后旧响应隔离及无横向溢出。截图写入忽略的 `.tmp/reading-data/`。

本阶段未执行线上数据修复、数据库迁移或服务重启。部署新版本后，由每位用户自行预览和确认处理自己的记录。
