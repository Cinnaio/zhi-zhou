# 备份与恢复首版落地

首版按已确认的 SFTP 优先顺序开发。本地加密全量备份、多个 SFTP 副本、自动日/周/间隔计划、指定版本回滚与独立日志已接入后台。前端沿用现有 Claude 风格的暖纸面与扁平面板，复用后台共用表格、表单、分页、状态、行内菜单和弹窗。

## 功能与范围

- 「备份版本」：立即备份、备注、各副本状态、详情、加密归档与恢复清单下载、固定保留、重试、删除、恢复预检与确认回滚。
- 「存储目标」：本地始终存在，支持多个 SFTP 目标，密码或未设置口令的专用 SSH 私钥认证，固定服务器公钥，启停、必需副本、各目标保留数量、真实上传/读取/删除连接测试。
- 「自动备份」：默认关闭，可设置每天、每周或固定小时间隔、IANA 时区、执行时间、目标与本地保留数量。重启漏计划补一次，多实例通过持久化记录及 advisory lock 去重。
- 「操作日志」：任务阶段、操作者、错误与脱敏记录，分页及级别筛选，查看任务，导出当前日志页。
- 数据保存在独立 `backup_control` schema；业务回滚不删除备份控制日志。业务会话失效，历史 AI/抓取队列不会因恢复而自动重新执行。
- 远程传输失败独立记录；本地归档仍可用。网络类失败按 1、5、15 分钟重试；身份、权限、空间问题不自动重试。所有目标完成才显示「全部完成」。
- 过期副本按目标的保留数量清理；固定与保护版本不参与淘汰，必需远程副本未完成时本地归档保留。手动删除拒绝最后一个可恢复版本。

当前远程协议为 SFTP。WebDAV/S3 类型预留，尚未启用；不提供任意 SSH 命令执行或网盘 OAuth。首版是全量快照恢复，不是任意时间点恢复，也不回退应用代码。不提供选择性恢复单本小说或用户。

数据库内封面、头像、候选封面与想法图片一起备份；外链图片只保存 URL。`.env`、部署主密钥与敏感运行时配置不打包。普通回滚保留当前服务器配置；明文恢复清单只包含模型名称等非敏感元数据和必须保管的配置名称。

## 部署准备

1. 发布代码并执行新迁移 `047_backups.sql`，服务启动也会自动迁移。数据库账号需能创建 `backup_control`，拥有独占的 `public` 业务 schema，具备导出、恢复及扩展重建权限。
2. 安装与 PostgreSQL 服务器大版本匹配的 `pg_dump`、`pg_restore`、`psql`。远程传输需安装 rclone。后台显示当前依赖就绪情况，缺失时相关动作不会开放。
3. 配置 `BACKUP_ENCRYPTION_KEY`，使用 32 字节随机密钥的 Base64，单独保存；`BACKUP_KEY_ID` 默认 `default`。当前单根密钥实现不支持透明轮换，保留旧归档期间不能直接更换主密钥，否则旧凭据和归档不可解密。
4. `BACKUP_ROOT` 默认 `data/backups`，需要持久化、足够磁盘空间，并放在静态目录之外；多实例必须共享这个目录、主密钥与控制数据库。文件与目录采用受限权限。
5. 在后台「备份设置」选择允许列表来源并填写服务器域名或 IP；也可选择使用部署端 `BACKUP_ALLOWED_HOSTS`，逗号分隔。回环、链路本地及云元数据地址始终拒绝。SFTP 配置需填写完整服务器公钥（算法与 Base64），从可信运维渠道核对，不仅是 SHA-256 指纹。
6. 在后台「备份设置」加密保存专用演练库连接，或选择使用部署端 `BACKUP_REHEARSAL_DATABASE_URL`，配置后才能在线回滚。该库必须与业务库不同名；演练会重建其 `public`，所以只允许专门用于演练的空库。

演练库由运维预先创建，连接后执行以下初始化。保护标记位于独立 schema，演练不会删除它：

```sql
CREATE SCHEMA backup_rehearsal;
CREATE TABLE backup_rehearsal.guard (
  key text PRIMARY KEY,
  value text NOT NULL
);
INSERT INTO backup_rehearsal.guard VALUES ('purpose', 'zhi-zhou-backup-rehearsal');
```

配置 `BACKUP_REHEARSAL_DATABASE_URL` 指向该库。演练账号需能重建 `public` 和必要扩展；也可由部署管理员提前配置扩展权限。若标记不存在、数据库名与业务库相同或权限不足，预检失败，不执行线上回滚。

工具路径可以通过 `BACKUP_PG_DUMP_PATH`、`BACKUP_PG_RESTORE_PATH`、`BACKUP_PSQL_PATH`、`BACKUP_RCLONE_PATH` 指定。数据库密码通过子进程环境传入，SFTP 材料用 0600 临时配置，任务日志不保存原始命令输出或认证材料。

备份 Worker 随 API 每 10 秒检查持久化队列；长任务不占用 HTTP 请求。启用恢复协调后，请求 gate 使用独立最多 24 条连接的池，避免和业务池竞争形成死锁；部署数据库应预留连接容量。回滚期间所有实例遵守共同的维护状态与 advisory lock。

## 回滚流程与中断处理

版本详情 → 预检恢复 → 真实隔离恢复与迁移验证 → 10 分钟内确认 → 输入完整版本标识与当前管理员密码 → 进入维护 → 检查在途请求及 AI/抓取任务 → 再演练 → 生成并校验固定保护备份 → 事务重建业务 schema、恢复并迁移 → 业务检查 → 解除维护、重新登录。

仍有 AI/抓取任务或在途业务请求时，本次恢复拒绝执行。保护备份生成失败也拒绝继续。事务内失败保留原库；提交后的检查失败尝试保护版本补偿恢复；无法证明提交状态或补偿失败时保持维护。数据库事务内的提交标记及 fsync 后的 `restore-journal.json` 用于诊断，不盲目重放恢复任务。

进程重启将遗留运行任务标记为中断，已经完整写出的副本继续保留。恢复中断不会自动关闭维护，请先停止所有 API/Worker，再通过灾备工具处理。

## 部署侧灾备工具

运行环境需要安装依赖与 tsx。下载时同时保存 `.zzbackup` 和 `.manifest.json`，主密钥另行保管。工具验证归档签名、摘要、密钥标识与版本确认，不依赖网页登录。

查看维护状态：

```bash
npm run backup:recover -- --status
```

停止所有 API/Worker 后，在配置好目标 `DATABASE_URL`、原备份主密钥与 `BACKUP_ROOT` 的环境下执行：

```bash
npm run backup:recover -- \
  --offline \
  --manifest /path/to/version.manifest.json \
  --archive /path/to/version.zzbackup \
  --confirm <恢复清单中的完整版本标识>
```

已有完整业务库时会先生成固定保护版本。向完全空的业务 schema 恢复时显式增加 `--empty-database`；仍有业务表时拒绝该选项。部分损坏到无法导出的数据库需要运维先留存现场并另建空库恢复。工具不会创建 PostgreSQL 数据库本身，目标库须预先存在。

恢复失败保留维护状态及日记；成功后可重新启动服务。首次灾备还需恢复部署侧 `SITE_SETTINGS_ENCRYPTION_KEY`、`SOURCE_ACCOUNT_ENCRYPTION_KEY` 等原配置材料，以解密业务库中的历史密钥；这些材料不包含在应用备份内。

## 本地主密钥与工具配置补充（2026-10-09）

备份设置页直接管理备份主密钥与 pg_dump、pg_restore、psql、rclone 路径，不再要求手工编辑环境变量。主密钥和工具路径写入独立的 data/backup-config.json，文件与目录分别以 0600 / 0700 创建（Windows 使用部署账户的文件访问控制）；不写入业务库或备份控制库，不包含在业务快照中。可用 BACKUP_CONFIG_FILE 指定另一个非静态资源目录，容器部署必须持久化该目录。该文件包含明文部署密钥，应限制服务账户访问并单独保管，不放入公开目录或版本控制。

- 优先级：本地文件 > 环境变量 / .env > 工具默认命令。路径留空移除本地覆盖，自动回退部署路径或 PATH。API Worker 与离线恢复 CLI 共用相同读取逻辑，服务重启后仍生效。
- 首次可输入已有的 32 字节 Base64 密钥，或由服务器生成并下载独立密钥文件，再点击保存。生成接口不写入配置；读取设置永不回显密钥，保存后清空输入。已有环境密钥可原样迁入本地，不改变密钥标识及归档解密能力。普通设置不提供密钥轮换，拒绝覆盖现有密钥；配置丢失后导入密钥须通过历史归档签名和已存凭据校验，并恢复原密钥标识。需要更换时须另行实现历史归档与凭据迁移。
- 每个工具分别显示来源、版本与检测错误。自定义路径必须是服务端绝对路径，使用固定 --version 参数且禁用 shell，校验 PostgreSQL / rclone 工具身份；检测不写文件，保存时再次检测，路径无效不保存。留空允许先保存密钥或其他工具，缺少的工具继续影响其对应功能。工具大版本与数据库的恢复兼容检查继续在原预检流程执行。
- 生成、检测与保存校验当前管理员登录态，不要求再次输入密码。保存与 Worker 共用任务锁，维护期间拒绝修改；文件 revision 防止旧草稿覆盖，使用同目录临时文件、fsync 与原子重命名，不通过页面编辑任意配置文件或命令参数。
- 本地与运行环境保留紧凑状态列表，点击主密钥或工具项打开配置弹窗；数据库恢复工具同时配置 pg_restore 与 psql。弹窗独立检测及保存，成功立即更新状态，保留页面其他业务草稿；关闭或取消撤销弹窗编辑并清除敏感输入，失败保留输入。主密钥弹窗支持一键生成并导出 32 字节随机数据的 Base64，再点击保存配置。业务设置继续使用页面底部统一保存/撤销，两种存储不宣称为跨资源原子事务。

灾备时除归档与清单外，还需恢复此文件或使用单独导出的主密钥；其他业务侧加密密钥仍按原灾备要求保管。
