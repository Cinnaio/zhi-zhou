# 功能缺陷修复：第二批（抓取数据与任务一致性）

本批修复服务器抓取链路中的落库失败假成功、普通重试重复章节、取消状态被旧阶段覆盖，以及抓取中心旧响应回退任务状态的问题。

## 行为变化

- 章节、对应任务项的 `saved` 状态、小说章节总数和任务成功数在同一事务中提交。正文获取成功只进入缓冲队列；事务成功后才计为保存成功。
- 批次落库失败时整批回滚，章节项标为失败并记录原因，允许通过原有失败章节重试入口恢复。前一批已成功保存的章节保留，部分成功呈现为 `partial`。
- 普通抓取、增量抓取及失败章节重试均先过滤已存在的章节。提交时先锁小说、再锁任务，重新按小说与来源 URL 去重，保留已有章节正文、ID 和顺序。来源 URL 相同的章节不会再次插入；本批不清理历史重复数据。
- 完整目录过滤前保留原位置，重试中间缺章时优先补回原目录序号；已占用的位置使用后续空位，避免产生新的顺序冲突。任务与章节 ID 增加随机部分，避免同一毫秒产生碰撞。
- 已取消、已结束的任务拒绝旧阶段和进度更新。运行中的阶段保存只更新已有任务，已删除任务不会因引擎迟到响应而重建。已提交成功数不会被旧进度或失败快照写回较小值。
- 目录分页、正文请求完成后及事务提交前均检查停止状态。取消保留已提交章节，拒绝继续提交缓冲章节；正在进行的网络请求可能仍需等待返回。
- 同一任务内批次串行提交；发生非预期 worker 异常时等待其他 worker 结束，再统一结算，避免提前写入最终状态。
- 抓取中心按已经应用的响应版本拒绝旧轮询结果，同时接纳耗时超过轮询周期的有效响应。移除任务或卸载页面后的旧响应不再更新任务卡。
- 整本重试和失败章节重试共用同步防重锁。请求失败释放锁，允许再次操作。终止提示改为“已提交终止请求”，最终状态由轮询确认。

- 修复前 6 项后端核心复现全部失败；新增“迟到进度回退已提交成功数”复现也先失败，再通过。前端迟到响应和重复重试复现先失败，再通过。
- 后端抓取相关 9 个测试文件、64 项通过，其中新增 13 项引擎/隔离数据库回归、2 项实际路由调用链回归。覆盖整批回滚、部分成功、取消时机、重复目录、事务内二次去重、缺章顺序、终态保护、已删除任务及成功数不回退。
- 实际路由回归通过认证 API 开始任务，执行真实引擎和隔离 PGlite 数据库，读取任务状态后执行普通重试或失败章节重试。成功数与数据库章节及任务项核对一致。
- 前端相关 4 个测试文件、30 项通过，其中新增 5 项状态 Hook 回归，覆盖迟到响应、慢轮询、移除后重新跟踪、防重提交和失败后重试。

## 兼容与边界

保持既有开始、取消和重试入口及请求结构；旧任务状态上传接口对不存在或已结束任务返回 409，不接受迟到写入。成功数表示该任务实际新增并提交的章节数，整本重试过滤全部已有章节时新增成功数可以为 0。

验证使用固定源站 HTML 和独立测试数据库，没有连接实际数据库执行写入、迁移、重复章节清理，也没有抓取真实账号的受保护正文。PGlite 回归验证事务和交错时序；尚未在真实 PostgreSQL 多连接环境进行并发压力测试。小说编辑等其他写入入口未统一纳入来源 URL 去重协议。

版本保持根项目 0.5.0、Web/API 0.3.0。本批只提交抓取相关源码、回归测试和此记录；工作区同时发生的小说导入修复由其他提交单独处理。
