# 功能缺陷修复：第一批（数据保护）

本批对应审查中的章节正文误清空、非法书签载荷清空、账号缓存混用、阅读器全量覆盖书签、旧设备复活收藏和书签，以及书签 ID 重复加前缀问题。

## 行为变化

- 编辑既有章节必须成功读取正文才能保存；读取失败显示重试入口，按钮和快捷键均禁止保存。成功读取后仍允许主动清空正文。迟到的读取响应不能覆盖新弹窗，保存用同步锁防止重复请求。
- 全量书签 PUT 先验证整个请求，非法 JSON、缺失数组、非法项或超过 500 条均返回 400，不执行删除事务。明确的空数组仍可清空。保留原有去重规则，并固定服务端 ID 前缀。
- 新增书签 POST 和 DELETE 单条接口。新增验证实际小说/章节关联及内容访问权限，以用户/小说/章节唯一键更新；删除仅作用于本人目标章节，重复删除保持成功。
- 阅读器先读取云端书签，增删只发送目标项。写失败保留本地数据；并发重复点击只发送一次；账号切换后的迟到响应不能写入新账号缓存。
- 阅读历史、书签、书架按服务端确认的用户 ID 缓存，游客独立。阅读器使用相同存储封装恢复历史，并等身份确认后恢复位置。账号切换后的延迟进度不发送给新账号。
- 书架读取及手动同步不再自动上传全部旧缓存；云端收藏和书签为权威。收藏删除失败保留原项并提示错误。

## 兼容与边界

原有书签全量 PUT 保留，但 Web 阅读器和书架不再调用它。其他客户端仍需要自行避免用局部数据调用全量替换。

旧版全局缓存没有可靠的账号归属，保留原存储键及内容，不自动认领、删除或上传。登录后的收藏和书签从云端重新读取；旧版仅存本机、未同步的数据需要后续提供显式恢复方案。

本批没有修改实际数据库数据、执行数据迁移或清理历史异常，也没有调整书架分页、阅读进度版本冲突和内容分级业务规则。版本保持根项目 0.5.0、Web/API 0.3.0。

- 后端相关 42 项通过，包含书签校验和隔离 PGlite 数据库 CRUD、认证、社交、内容访问与健壮性检查。测试数据库与实际数据库独立。
