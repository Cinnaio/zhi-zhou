# 用户管理项目落地与验收（2026-10-01）

页面：`/admin/settings?view=users`。将已确认的 `docs/previews/user-management-claude.html` 设计落到实际用户目录，复用 AdminPage、AdminDataPanel、AdminStatusBadge、Pagination、Radix 下拉菜单和三段式 AdminDialog。保留共享暖灰底色、白色无外描边面板、奶茶棕操作及既有字号；不改变注册与邀请码、登录审计的业务流程。

## 页面与接口

- 页头搜索昵称或用户名，400ms 防抖；目录内筛选角色和状态；服务端分页默认 15 人，支持 15 / 20 / 50 / 100。
- 目录分为用户、权限与状态、注册与登录、想法、操作五列；手机端复用共享卡片布局与触摸操作尺寸。本人标记及未登录记录保留。
- 每行直接修改密码；更多菜单保留角色调整、生成临时密码、禁用或恢复、删除及其原确认流程。
- 新增 `GET /api/admin-users/users`，对完整用户集合搜索与分页，解决原接口最多返回 100 人的限制。角色与状态白名单校验，搜索按参数化 SQL 转义 LIKE 通配符，以注册时间、用户 ID 稳定排序。原 `/admin-users` 设置接口保持兼容。
- 新增 `POST /api/admin-users` 的 `set-password` action：管理员鉴权、新密码至少 8 位、目标存在且不是本人，复用 PBKDF2 哈希及随机盐。密码更新、目标会话清除、成功操作审计在同一事务中；会话清除失败时全部回滚。仅返回 success，不返回密码。
- 操作审计保存管理员、动作、目标范围与时间等元数据，不保存密码、盐或请求正文摘要。操作审计列表将 `set-password` 显示为“修改用户密码”。
- 本人必须填写当前密码，沿用 `/auth/change-password` 验证并更新当前 token；其他登录会话失效，当前登录保留。修改禁用用户的密码不会解除禁用。
- 密码与确认输入一致性校验、显示密码、保存期间防重复及关闭、错误提示和重试；关闭或成功后清空输入。目录请求失败保留最后一次成功数据并显示重试入口，过期请求不能覆盖新结果。
